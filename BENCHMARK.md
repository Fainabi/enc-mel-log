# Benchmark Record

This file is the self-contained benchmark record for the code in this directory. The
primary numbers are the ones used in the ICASSP 2027 manuscript. The packed end-to-end
prototype and the staged operator accounting are separate measurements and must not be
added together.

## Latest Complex-CKKS Repair Run (OpenFHE v1.4.0)

This run uses the OpenFHE v1.4.0 source build. OpenFHE 1.2.4 does not support
complex CKKS arithmetic and is not valid for the complex-packing experiment.
The DCT uses the same BSGS matrix-vector path as projection and mel.

| --- | --- |

| Ring dimension | `N=2^16` |
| Chebyshev interval | `[-1e-2, 1e-2]` |
| Runtime | 39.447 s |
| Projection / mel / Chebyshev / DCT | 24.413729 / 10.305156 / 2.423538 / 2.247688 s |
| Endpoint RMSE | `9.729762e-03` |
| Endpoint max error | `1.194064e-02` |
| Remaining levels | 16 |

Stage errors were: `packed_mel` RMSE `1.809016e-05`, `recombine_c` RMSE
`1.288350e-02`, and `dct_vs_decoded` max error `4.811513e-03`.

Build configuration:

```sh
cmake -S he-frontend -B build-v140 \
  -DOPENFHE_SOURCE_DIR=/path/to/openfhe-v1.4.0 \
  -DOPENFHE_BUILD_DIR=/path/to/openfhe-v1.4.0-build
cmake --build build-v140 --target cpp_complex_e2e -j2
```

## Primary 64-Frame Packed Run

Reference output: `../results/cpp_complex_fft3_64.log`

| Field | Value |
| --- | --- |
| Program | `cpp_complex_e2e` |
| Pipeline | STFT projection -> modulus-square -> mel -> degree-63 Chebyshev compressor -> DCT |
| Projection | Three-stage radix-8 DFT, with complex packing (`512 = 8^3`) |
| Batch | 64 frames = 0.64 s of audio at a 10 ms hop |
| Packing | 32 blocks, two 512-slot frame lanes per block |
| Ring dimension | `N=2^16` |
| Scale | 59-bit scaling modulus |
| Security | `HEStd_128_classic` |
| OpenFHE | 1.4.0, complex CKKS packing |
| Host | Intel Xeon Gold 6230R |
| Threading | OpenFHE default OpenMP configuration; exact thread count is not recorded in the primary log |
| Input | Deterministic synthetic signal generated by the program |
| Timing | Ciphertext evaluation only. Setup, key generation, encoding, encryption and decryption are excluded |
| Batch runtime | 43.800 s |
| Normalized runtime | 68.4375 s/s, reported as 68.44 s/s |
| Endpoint RMSE | `8.436337e-03` |
| Endpoint max error | `8.973544e-03` |
| Remaining levels | 5 before the configured ceiling after the packed projection/interleaving operations |

The normalized runtime is `43.800 / 0.64 = 68.4375` seconds per second of audio.
The measured stage times are:

| Stage | Batch seconds | Seconds per second of audio |
| --- | ---: | ---: |
| Complex-packed projection | 22.710301 | 35.4848 |
| Mel transform | 9.747905 | 15.2311 |
| Chebyshev compressor | 5.058857 | 7.9045 |
| DCT | 6.220999 | 9.7203 |
| Sum of stage timers | 43.738062 | 68.3407 |
| End-to-end timer | 43.800000 | 68.4375 |

The manuscript reports mel+DCT as 24.95 s/s after rounding. Linear stages account for
`(22.710301 + 9.747905 + 6.220999) / 43.800 = 88.3%` of this degree-63 measurement.

The RMSE reference is the plaintext execution of the same degree-63 Chebyshev chain. It
checks the encrypted implementation path against plaintext and is not a real-speech task
accuracy result. LibriSpeech is used by the separate dynamic-range and downstream accuracy
experiments, not by this synthetic timing input.

## Reproduction

Build and run from this directory:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target cpp_complex_e2e -j
E52_BENCH=1 scripts/run_bench.sh
```

The script writes a timestamped log under `logs/`. Set `OMP_NUM_THREADS` explicitly when
comparing machines, and record the host, OpenFHE version, thread setting, and wrapper runtime.
The reference `runtime_s` excludes setup and should be compared separately from
`wrapper_elapsed_s`.

## Scope and Non-Primary Logs

- The primary run uses 64 frames. Earlier 32-frame and failed repacking variants are not
  manuscript results.
- The source program does not accept real speech. It generates the deterministic synthetic
  input used for timing and plaintext-agreement checks.
- The primary log is retained outside this git directory at
  `../results/cpp_complex_fft3_64.log`.
- Other exploratory logs under `../results/` include failed split/repacking layouts and
  different parameter settings. They should not be used to reproduce Table 3.
